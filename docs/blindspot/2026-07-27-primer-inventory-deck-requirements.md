여기서 푸는 말은 **이 문서를 읽는 사람**을 위한 것입니다.
이 문서를 읽는 사람이 모를 수 있는 말을 골랐습니다.
개발과 도구에서 온 말이 대부분이고, 이 프로그램 출력에서 온 말도 하나 있습니다.

발표를 들을 매니저에게는 다른 기준이 적용됩니다.
매니저는 실험 전문가이므로 슬라이드에서는 생물 용어를 풀지 않습니다.
그 규칙은 아래 확정 요구사항 2번에 적었습니다.
반대로 개발과 도구에서 온 말은 슬라이드에서도 짧게 풀어 씁니다.
매니저는 실험 전문가이지 개발자가 아니기 때문입니다.

- **웹 브라우저로 넘겨 보는 발표자료 도구(reveal.js)**: 슬라이드를 웹 페이지로 만들어 주는 도구입니다.
- **어두운 우주 배경 디자인(galaxy)**: 이 저장소가 쓰는 발표자료 디자인입니다.
- **모르는 것을 찾아내는 다음 단계(blindspot-pass)**: 이 작업 방식의 두 번째 단계 이름입니다.
- **코드를 저장한 시점(커밋)**: 코드가 저장된 특정 시점을 가리키는 이름표입니다.
- **작업 갈래(브랜치)**: 코드를 여러 줄기로 나누어 작업하는 단위입니다.
- **오류 없이 끝났다는 신호(종료 코드 0)**: 프로그램이 문제없이 끝났다는 표시입니다.
- **글자 너비가 모두 같은 글꼴(등폭 글꼴)**: 표와 그림이 어긋나지 않게 해 주는 글꼴입니다.
- **화면 폭(칸)**: 등폭 글꼴에서 한 줄이 차지하는 칸 수입니다.
  한글 한 글자는 두 칸을 차지합니다.
- **글로 쓴 안내 파일(README)**: 저장소를 열었을 때 가장 먼저 보이는 설명 파일입니다.
- **글자만으로 쓰는 문서 형식(마크다운)**: 별표와 우물 정 기호로 서식을 표시하는 문서 형식입니다.
- **터미널 명령 도구**: 창을 띄우지 않고 글자를 쳐서 쓰는 프로그램입니다.
- **덮임 그림(커버리지)**: 목표 구간 중 어디까지 읽히는지 보여주는 그림입니다.
  이 프로그램이 직접 그려 내는 그림의 이름입니다.

## 확정 요구사항

1. **청중은 매니저다.**
   사용자 답변: "청중은 매니저입니다. 전체 프로젝트의 구조와 방향성을 설명하고 피드백 받을 예정입니다."
   따라서 발표자료는 사용법 교육 자료가 아닙니다.
   프로젝트를 보고하고 의견을 구하는 브리핑 자료입니다.

2. **생물 실험 용어는 설명하지 않는다.**
   사용자 답변: "실험 전문가라 다 알고 있음."
   시퀀싱, primer, 녹는점 같은 개념은 아는 것으로 전제합니다.
   그렇게 아낀 분량은 판정 기준과 설계 결정을 설명하는 데 씁니다.

3. **마무리에 논의 요청 항목 네 가지를 넣는다.**
   사용자가 네 가지를 모두 골랐습니다.
   - 판정 기준이 실험적으로 타당한가
   - 다음에 무엇을 만들지 우선순위
   - 프로젝트 범위가 맞는가
   - 실제 랩 운영에 붙일 수 있는가

   본론은 이 네 가지 논의를 뒷받침하는 근거로 구성합니다.

4. **본론 분량은 20분 발표 기준으로 20장에서 25장 사이다.**
   사용자 답변: "표준 20분 (20~25장)."
   질문 대비 부록은 이 장수에 넣지 않고 따로 셉니다.

5. **사용법은 2장에서 3장까지만 다룬다.**
   사용자가 정리 축의 하나로 사용법을 지정했습니다.
   다만 청중이 매니저이므로 따라 하는 안내서가 되면 안 됩니다.
   이 2~3장 안에 실행 화면 슬라이드가 포함됩니다.
   명령 한 줄과 그 결과 화면을 보여주는 수준까지만 넣습니다.
   자세한 옵션 목록은 넣지 않습니다.

6. **화면에 꺼내는 수준은 세 가지다.**
   사용자 답변: "위에 더해 핵심 계산 코드도."
   - 명령을 쳤을 때 나오는 실제 실행 화면
   - 주요 파일 5개가 각각 무슨 일을 하는지 적은 역할표
   - 결과를 좌우하는 핵심 계산 부분의 파이썬 코드 일부

   여기서 핵심 계산이란 두 부분을 말합니다.
   하나는 primer가 붙었는지 판정하는 부분입니다.
   다른 하나는 녹는점을 계산하는 부분입니다.
   두 부분을 모두 싣습니다.
   어느 함수를 실을지는 unknowns 문서에서 확정했습니다.
   두 부분이 한 함수에 들어 있어 한 장으로 해결됩니다.

7. **실행 화면은 실제로 돌린 결과를 쓴다.**
   자체 해소한 항목입니다.
   2026-07-27에 대상 저장소를 내려받아 직접 실행했습니다.
   실행에 성공했고 오류 없이 끝났습니다(종료 코드 0).
   따라서 안내 파일(README)에 적힌 예시가 아니라 실제 출력을 씁니다.
   실제 출력은 48줄입니다.
   가장 넓은 줄의 화면 폭은 127칸입니다.
   그 줄의 글자 수는 85자입니다.
   글자 수와 화면 폭이 다른 이유는 한글이 두 칸을 차지하기 때문입니다.

8. **첫 화면 목록에 새 발표자료 카드를 추가한다.**
   자체 해소한 항목입니다.
   근거는 `index.html:20-33`이 발표자료 목록을 직접 적어 두는 방식이라는 점입니다.
   카드에는 제목과 한 문장 설명과 날짜와 슬라이드 장수가 들어갑니다.
   장수는 발표자료를 다 만든 뒤 실제 장수로 적습니다.
   이때 적는 장수는 본론과 질문 대비 부록을 합친 전체 장수입니다.
