# primer-inventory 발표자료 스크립트 작성 및 디자인 개편 설계 문서

- 날짜: 2026-07-27
- 입력: [요구사항 문서](2026-07-27-primer-inventory-deck-script-redesign-requirements.md), [unknowns 문서](2026-07-27-primer-inventory-deck-script-redesign-unknowns.md)

## 이 문서를 읽기 위한 말

낯선 말을 먼저 풀어 둡니다.
여기서 푸는 말은 이 문서를 읽는 사람을 위한 것입니다.
발표를 들을 매니저를 위한 것이 아닙니다.

- **덱**: 발표자료 한 벌입니다. 이 저장소에서는 파일 하나가 덱 하나입니다.
- **발표자 화면**: 발표 중 발표자만 보는 별도 창입니다. `S` 키를 누르면 열립니다.
  현재 슬라이드와 다음 슬라이드와 노트와 시계가 함께 나옵니다.
- **발표자 노트**: 슬라이드마다 붙여 두는 메모입니다.
  청중 화면에는 안 보이고 발표자 화면에만 나옵니다.
- **화면 크기**: 슬라이드 한 장을 그릴 때 쓰는 가상의 가로세로 값입니다.
  실제 화면에 그릴 때는 이 값을 화면에 맞게 늘리거나 줄입니다.
- **기준 글자 크기**: 슬라이드 안의 모든 글자 크기가 매달려 있는 하나의 값입니다.
- **칸**: 글자 너비가 모두 같은 글꼴에서 글자 한 자리입니다. 한글 한 글자는 두 칸입니다.
- **원문 상자**: 터미널 화면과 코드를 그대로 담아 둔 상자입니다. 덱에 여덟 개 있습니다.
- **키를 눌러 하나씩**: 방향키를 누를 때마다 항목이 하나씩 나타나는 방식입니다.
- **자동 등장**: 슬라이드가 뜨면 내용이 저절로 순서대로 나타나는 방식입니다.
- **전체 보기**: `ESC` 키를 누르면 모든 슬라이드가 바둑판처럼 펼쳐지는 화면입니다.
- **움직임 줄이기 설정**: 어지럼증 등을 이유로 애니메이션을 꺼 달라는 운영체제 설정입니다.
- **글자 선명도(대비)**: 글자색과 배경색이 얼마나 다른지를 나타내는 값입니다.
  4.5가 최소 기준이고 7이 권장 기준입니다.
- **여러 곳이 함께 쓰는 파일**: 첫 화면과 견본 덱과 이 덱이 같이 불러 쓰는 파일입니다.
- **자동 검사(CI)**: 코드를 올릴 때마다 저장소가 스스로 돌리는 확인 절차입니다.
- **형제 순서**: 같은 부모 아래 나란히 놓인 요소들의 차례입니다.
  등장 순서를 정할 때 이 차례를 셉니다.
- **부모 껍데기**: 부록이 달린 슬라이드에서 본문과 부록을 함께 감싸는 바깥 상자입니다.
  그 자체는 화면에 보이지 않습니다.
- **글자 폭 보정**: 한글 폭이 영문의 정확히 두 배가 아닐 때 글자 사이를 벌려 표를 맞추는 장치입니다.
  지난 작업에서 이 덱 안에 넣었습니다.
  글꼴이 바뀌면 이 보정값도 다시 계산됩니다.

## 목적과 배경

사용자는 어제 발표자료 한 벌을 만들었습니다.
`primer-inventory`라는 프로그램을 매니저에게 설명하는 자료입니다.
그 프로그램은 실험실이 가진 primer 중에서 시퀀싱에 쓸 것을 골라 줍니다.
슬라이드는 모두 28장입니다.

이제 세 가지를 더 합니다.

첫째, 발표할 때 볼 **스크립트**를 만듭니다.
둘째, 그 스크립트를 **발표자 화면**에서 볼 수 있게 합니다.
셋째, 전체 **디자인과 움직임**을 다른 사이트를 참고해 새로 만듭니다.

참고할 사이트는 `euiyun.com` 입니다.
그 사이트에는 성격이 다른 디자인이 두 개 있습니다.
주소를 그냥 치면 나오는 메인 페이지는 밝은 테마입니다.
주소 뒤에 `/seminar/vibe-coding/`이 붙는 발표자료들은 어두운 테마입니다.
사용자가 참고하라고 한 것은 어두운 발표자료 쪽입니다.

## 지금 상태와 무엇이 문제인가

### 스크립트가 아니라 메모다

지금도 28장 전부에 노트가 붙어 있습니다.
전부 합쳐 2,603자이고 평균 93자입니다.
소리 내어 읽으면 약 9분치입니다.

문제는 분량이 아니라 편차입니다.
가장 긴 것은 165자이고 가장 짧은 것은 23자입니다.
가장 짧은 넷은 화면 12·20·22·25번입니다.
그중 셋은 부록이고 하나는 다음 대목으로 넘어가는 장입니다.
그 셋을 포함해 부록 넷 전부가 55자 이하입니다.
"질문이 나오면 보여 준다"는 안내만 있습니다.
그 부록을 실제로 꺼냈을 때 할 말이 없습니다.

또 하나, 노트 원문은 여러 줄로 적혀 있는데 화면에서는 한 덩어리로 붙어 나옵니다.
줄바꿈 표시를 쓰지 않았기 때문입니다.

### 발표자 화면 상자가 생각보다 작다

발표자 화면은 가로 1100, 세로 700 크기의 새 창으로 열립니다.
그 안에서 노트가 차지하는 자리는 가로 440, 세로 420입니다.
위쪽 약 110을 시계와 타이머가 씁니다.

이 상자를 그대로 재현해 재 봤습니다.
스크롤 없이 들어가는 양은 **144자에서 180자** 사이였습니다.
글자 크기가 화면 폭에 따라 갈리기 때문입니다.

넘치면 잘리지는 않고 스크롤이 생깁니다.
다만 발표 도중에 마우스로 스크롤하는 것은 사고나기 쉽습니다.

### 화면을 키우면 글자가 오히려 작아진다

이것이 이번 작업에서 가장 뜻밖의 발견입니다.

슬라이드는 가상의 크기로 그린 뒤 화면에 맞게 늘려 보여 줍니다.
지금 가상 크기는 가로 960, 세로 700입니다.
이것을 가로 1280, 세로 800으로 바꾸면 그릴 자리가 넓어집니다.

그런데 기준 글자 크기 42는 가상 크기와 무관한 고정값입니다.
가상 크기가 커지면 화면에 맞추느라 더 많이 줄여야 합니다.
그래서 **화면 위 실물 글자가 12.5퍼센트 작아집니다.**

발표 화면이 16대9라는 것은 사용자에게 확인했습니다.
가로세로가 4 대 3인 화면이었다면 25퍼센트까지 작아질 뻔했습니다.

### 키 입력 표시를 없애면 세 곳이 무너진다

지금은 항목이 방향키를 눌러야 하나씩 나옵니다.
그런 항목이 28개 있습니다.
이것을 자동 등장으로 바꾸려 합니다.

그런데 이 표시에는 세 가지가 딸려 있었습니다.

첫째, 전체 보기에서 내용을 강제로 보이게 하는 안전장치입니다.
둘째, 인쇄할 때 내용을 보이게 하는 안전장치입니다.
셋째, 움직임 줄이기 설정에서 내용을 보이게 하는 안전장치입니다.

표시를 없애면 이 셋이 함께 사라집니다.
그러면 전체 보기를 열었을 때 슬라이드 대부분이 백지로 보입니다.

또 하나, 코드 슬라이드의 줄 강조도 **같은 표시**로 만들어집니다.
전역 규칙을 걸면 강조 단계가 겹쳐 찍혀 강조 기능이 사라집니다.

## 무엇을 만드는가

파일 하나만 고칩니다.
`slides/primer-inventory/index.html` 입니다.

여러 곳이 함께 쓰는 파일은 건드리지 않습니다.
색 파일 둘과 별 배경 파일과 그 검사 파일입니다.
그 파일들을 고치면 첫 화면과 견본 덱까지 바뀌기 때문입니다.

## 결정사항

| # | 결정 | 근거 |
|---|---|---|
| 1 | 참고 대상은 어두운 발표자료 쪽으로 한다 | 사용자가 그쪽을 보고 말했다. 지금 덱과 골격이 같아 색과 움직임을 그대로 옮길 수 있다 |
| 2 | 스크립트는 요점 나열과 꼭 짚을 문장을 섞어 쓴다 | 사용자 지시다. 그대로 읽는 대본은 톤이 딱딱해지고 청중과 눈을 못 맞춘다 |
| 3 | 슬라이드당 스크립트는 140자를 넘지 않는다 | 발표자 화면에 스크롤 없이 들어가는 양이 144자에서 180자다. 가장 나쁜 값보다 조금 낮게 잡는다 |
| 4 | 노트에 줄바꿈과 굵은 글씨 표시를 직접 넣는다 | 발표자 화면은 그냥 줄을 바꿔 쓴 것을 무시한다 |
| 5 | 본론 24장의 노트를 네 덩이로 나눠 같은 순서로 쓴다 | 같은 구조여야 발표 중에 눈이 위치를 외운다 |
| 6 | 부록 4장(화면 12·20·21·25번)은 짧은 규격을 따로 쓴다 | 부록은 질문이 나올 때만 꺼낸다. 본론과 같은 분량이 필요 없다 |
| 7 | 슬라이드를 부를 때는 화면 번호 1에서 28을 쓴다 | 덱에 번호가 두 벌 있다. 본론만 세는 1에서 24와 부록까지 세는 1에서 28이다. 지난 작업에서 이 혼동이 실제 오류로 잡혔다 |
| 8 | 화면 크기를 가로 1280, 세로 800으로 바꾼다 | 사용자 지시다. 참고 덱과 같은 크기다 |
| 9 | 기준 글자 크기를 42에서 48로 함께 올린다 | 안 올리면 화면 위 글자가 12.5퍼센트 작아진다. 올리면 넓어진 가로만 이득으로 남는다 |
| 10 | 원문 상자 8개는 폭과 세로를 각각 계산해 작은 값을 쓴다 | 여섯은 폭이 상한이고 코드 두 장은 세로가 상한이다 |
| 11 | 원문 상자의 높이 제한 480을 덱 안에서 없앤다 | 새 크기에서 상자 셋이 그 값을 넘는다. 슬라이드 세로 800이 유일한 상한이 된다 |
| 12 | 터미널 화면과 코드의 원문은 한 글자도 바꾸지 않는다 | 지난 작업의 원칙을 잇는다. 작업 후 원본과 기계로 다시 대조한다 |
| 13 | 색은 참고 덱의 팔레트를 그대로 쓴다 | 배경 세 단계와 글자 세 단계와 강조 네 개다 |
| 14 | 밝은 화면 모드용 강조색 네 개를 새로 만든다 | 참고 덱 색을 밝은 배경에 그대로 쓰면 선명도가 최소 기준에 전부 미달한다 |
| 15 | 색을 덮어쓸 때 어두운 모드와 밝은 모드를 쌍으로 쓴다 | 밝은 모드 규칙이 더 강해서, 한쪽만 쓰면 밝은 모드에서 새 색이 통째로 사라진다 |
| 16 | 배경은 별을 그대로 두고 그 위에 두 겹을 얹는다 | 사용자 지시다. 별 배경 파일을 안 건드리므로 첫 화면과 견본 덱이 영향을 안 받는다 |
| 17 | 키 입력 표시 28개를 실제로 제거한다 | 남겨 두고 화면에서만 보이게 하면 아무 반응 없는 키 입력이 28번 생긴다 |
| 18 | 코드 줄 강조 두 장만 방향키로 넘긴다 | 줄 강조도 같은 표시로 만들어진다. 위치로 구분해 규칙에서 뺀다. 안 빼면 강조 단계가 겹쳐 찍힌다 |
| 19 | 처음 모습을 애니메이션 규칙 안에만 둔다 | 움직임이 안 걸리는 모든 상황에서 내용이 저절로 보인다. 안전장치 셋을 한 번에 되살린다 |
| 20 | 순서가 논지인 5장은 지연을 길게 준다 | 사용자 지시다. 키 조작은 없다 |
| 21 | 발표자 화면과 인쇄에서는 애니메이션을 끈다 | 발표자가 다음 내용을 확인하려는데 빈 화면부터 다시 보면 안 된다 |
| 22 | 지연 단계를 12까지 만든다 | 지연은 형제 순서로 센다. 우리 덱의 최댓값이 여섯이라 일곱이면 충분하다. 나중에 늘어도 버티도록 다섯을 더 둔다 |
| 23 | 1번 슬라이드의 자동 변형 표시를 제거한다 | 지금 아무 일도 안 하고, 나중에 짝이 생기면 등장 애니메이션을 조용히 무력화한다 |
| 24 | 글꼴 파일을 새로 부르지 않는다 | 부르면 글자 폭 보정이 옛 글꼴로 재고 끝나 표가 통째로 어긋난다 |
| 25 | 새 코드는 원문 상자 여덟 개보다 뒤에 넣는다 | 지금 코드가 거기 있어 한자리에 모으는 편이 찾기 쉽다. 앞 단계 문서는 앞에 두면 검사가 반드시 실패한다고 적었으나, 직접 시험해 보니 사실이 아니었다 |
| 26 | 코드 구문 색을 새 팔레트로 바꾼다 | 밝은 화면 모드에서도 코드 상자만은 어두운 채로 남는다. 그 어두운 배경 위 주석 색이 선명도 3.62로 최소 기준 4.5에 미달한다 |
| 27 | 원문 상자 밖의 글자 크기 57곳은 손대지 않는다 | 요구사항은 새 세로를 기준으로 다시 정하라고 했다. 다시 계산해 보니 기준 글자를 함께 올려 값이 그대로였다 |

## 검토한 대안과 트레이드오프

| 결정 | 채택안 | 기각안 | 기각 이유 |
|---|---|---|---|
| 참고 대상 | 어두운 발표자료 쪽 | 메인 페이지의 밝은 테마 | 어두운 28장을 통째로 밝게 뒤집는 대공사가 된다. 참고 덱 제작자도 슬라이드에 밝은 테마를 금지했다 |
| 스크립트 형태 | 요점과 꼭 짚을 문장 | 그대로 읽는 완전 대본 | 완전한 문장으로 적으면 그대로 읽게 되어 톤이 딱딱해진다. 발표자 화면 상자에도 안 들어간다 |
| 스크립트 형태 | 요점과 꼭 짚을 문장 | 지금 메모를 그대로 두기 | 부록 넷은 23자에서 55자뿐이라 꺼냈을 때 할 말이 없다 |
| 분량 상한 | 140자 | 200자 | 실측하니 가장 나쁜 경우 144자였다. 200자면 발표 중에 스크롤해야 한다 |

그래서 위에서 아래로 순서대로 나타납니다.

**처음 모습을 애니메이션 규칙 안에만 둡니다.**
이것이 이번 설계에서 가장 중요한 한 가지입니다.

기본 규칙에 "안 보임"을 두면 애니메이션이 안 걸리는 곳에서 영원히 안 보입니다.
그런 곳이 셋입니다.
전체 보기와 인쇄와 움직임 줄이기 설정입니다.

애니메이션 규칙 안에만 두면 반대가 됩니다.
애니메이션이 걸리는 곳에서만 숨었다가 나타납니다.
안 걸리는 곳에서는 처음부터 그냥 보입니다.
예외를 따로 뚫지 않아도 세 곳이 전부 해결됩니다.

**코드 줄 강조는 예외로 둡니다.**
줄 강조도 같은 방식으로 만들어지기 때문입니다.
전역 규칙을 걸면 다섯에서 여섯 단계가 겹쳐 찍힙니다.
그러면 전 줄이 다 밝은 코드가 되어 강조가 사라집니다.
그래서 원문 상자 안에 있는 것은 규칙에서 뺍니다.

**부록이 달린 슬라이드도 주의합니다.**
그 슬라이드는 부모와 자식 양쪽에 "지금 보임" 표시가 붙습니다.
규칙에서 부모 껍데기를 빼지 않으면 부록이 통째로 밀려 올라옵니다.

**순서가 논지인 5장은 지연을 길게 줍니다.**

| 화면 | 제목 | 등장 항목 | 어떻게 | 왜 |
|---|---|---|---|---|
| 9 | 그런데 기본값은 더 보수적입니다 | 1개 | 기다리는 시간 1.2초 | 표를 보인 뒤 결론 문장이 와야 한다 |
| 13 | 파일 다섯 개, 역할이 겹치지 않습니다 | 1개 | 기다리는 시간 1.2초 | 표를 보인 뒤 주장 문장이 와야 한다 |
| 15 | 어떻게 검증했나 | 4개 | 항목 사이 0.5초 | 네 단계 순서 자체가 요지다 |
| 19 | 이미 있는 도구로는 안 되나 | 1개 | 기다리는 시간 1.2초 | 비교표를 보인 뒤 결론이 와야 한다 |
| 26 | 논의 ③ 프로젝트 범위가 맞는가 | 2개 | 항목 사이 0.5초 | 질문을 던진 뒤 답이 와야 한다 |

항목이 여럿인 두 장은 항목 사이 간격을 0.15초에서 0.5초로 넓힙니다.
항목이 하나뿐인 세 장은 나타나기까지 기다리는 시간을 1.2초로 늘립니다.
이 값들은 구현 중 실제로 보면서 조정할 수 있습니다.

**발표자 화면과 인쇄에서는 애니메이션을 끕니다.**
발표자가 다음 내용을 확인하려는데 빈 화면부터 다시 보면 안 됩니다.
인쇄에서는 코드 상자가 복제되어 애니메이션이 다시 시작합니다.

### 만드는 순서

1. 화면 크기와 기준 글자 크기를 바꿉니다.
2. 새 색과 배경 두 겹을 덱 안 스타일로 넣습니다. 어두운 모드와 밝은 모드를 쌍으로 씁니다.
3. 원문 상자 8개의 글자 크기를 새 값으로 바꿉니다. 상자 높이 제한도 없앱니다.
4. 코드 구문 색을 새 팔레트로 바꿉니다.
5. 키 입력 표시 28개를 제거하고 새 표시를 붙입니다.
6. 자동 등장 규칙을 넣습니다. 원문 상자 안과 부모 껍데기를 예외로 둡니다.
7. 지연 단계를 12까지 만듭니다.
8. 순서가 논지인 5장에 긴 지연을 줍니다.
9. 발표자 화면과 인쇄에서 애니메이션을 끄는 규칙을 넣습니다.
10. 1번 슬라이드의 자동 변형 표시를 제거합니다.
11. 본론 24장의 노트를 네 덩이 구조로 다시 씁니다. 부록 4장은 짧은 규격으로 씁니다.
12. 원문 여덟 상자가 한 글자도 안 바뀌었는지 원본 파일과 기계로 대조합니다.
13. 브라우저로 열어 확인합니다. 확인 항목은 아래에 적었습니다.

### 만든 뒤 무엇을 확인하는가

자동 검사는 이 변경을 거의 검증하지 못합니다.
문법과 파일 경로만 봅니다.
화면이 어떻게 보이는지는 사람이 봐야 합니다.

아래 여덟 가지를 손으로 확인합니다.

| 확인할 것 | 어떻게 |
|---|---|
| 슬라이드가 세로로 안 넘치는가 | 28장 전부의 높이를 재서 800 이하인지 본다 |
| 원문 상자가 가로로 안 넘치는가 | 8개 상자의 폭을 재고 표 정렬도 함께 본다 |
| 전체 보기가 백지가 아닌가 | `ESC`를 눌러 28장 미리보기에 내용이 보이는지 본다 |
| 인쇄가 비지 않는가 | 주소 뒤에 `?print-pdf`를 붙여 열어 본다 |
| 발표자 화면이 정상인가 | `S`를 눌러 노트가 스크롤 없이 보이는지, 미리보기가 빈 화면부터 시작하지 않는지 본다 |
| 밝은 모드 글자가 읽히는가 | 주소 뒤에 `?light`를 붙여 28장 전부의 선명도를 잰다 |
| 움직임 줄이기 설정에서 내용이 보이는가 | 운영체제 설정을 켜고 28장을 넘겨 본다. 사라지는 내용이 없어야 한다 |
| 원문이 한 글자도 안 바뀌었는가 | 원본 파일과 기계로 대조한다. 글자 폭 보정이 새 글자 크기에서도 표를 맞추는지 함께 본다 |

## 의도적 범위 제외

- **슬라이드 내용 재구성.**
  참고 덱에는 "본문 여섯 줄 이하" 규칙이 있습니다.
  따르려면 지금 28장 중 일부를 나누거나 줄여야 합니다.
  사용자가 요청한 것은 스크립트와 발표자 화면과 디자인 세 가지입니다.

- **참고 덱의 카드와 알약 모양 꾸밈.**
  그 꾸밈은 슬라이드 내용 구조를 바꿉니다.
  사용자가 요청한 것은 색과 움직임입니다.

- **여러 곳이 함께 쓰는 파일 수정.**
  색 파일 둘과 별 배경 파일과 그 검사 파일입니다.
  고치면 첫 화면과 견본 덱까지 바뀝니다.

- **견본 덱 수정.**
  지난 작업의 원칙을 잇습니다.

- **글꼴 파일 도입.**
  부르면 글자 폭 보정이 옛 글꼴로 재고 끝나 표가 어긋납니다.

- **자동 세로 배치 방식 변경.**
  참고 덱은 슬라이드마다 직접 배치합니다.
  따르려면 28장 전체를 다시 짜야 합니다.

- **대상 저장소 `primer-inventory` 수정.**
  지난 작업과 같습니다.

- **레이아웃 자동 검사 추가.**
  세로 800과 상자 폭을 지켜 주는 검사가 없습니다.
  이번에도 손으로 확인합니다.
  검사를 만드는 것은 요청 범위 밖입니다.
