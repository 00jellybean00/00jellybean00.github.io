primer-inventory 발표자료 28장에 발표자용 스크립트를 붙였습니다. 발표 중 S 키를 누르면 뜨는 발표자 화면에서 그 스크립트가 보입니다. 28장 모두 스크롤 없이 읽히도록 길이를 8줄 이내로 맞췄습니다. 가장 긴 장도 여유가 38픽셀 남습니다.

화면 비율을 4 대 3에서 16 대 9로 바꿨습니다. 넓어진 만큼 글자가 작아 보여서 기준 글자 크기도 함께 키웠습니다. 터미널 화면과 코드를 담은 상자 여덟 개도 새 크기에 맞춰 다시 키웠습니다. 상자 크기는 어림값이 아니라 브라우저에서 직접 잰 값으로 계산했습니다.

디자인을 어두운 세미나 발표자료 분위기로 바꿨습니다. 항목이 아래에서 떠오르며 하나씩 나타납니다. 전에는 발표자가 키를 눌러야 항목이 하나씩 열렸습니다. 이제는 슬라이드에 들어가면 저절로 차례로 나타납니다. 그래서 발표 중 키 입력 28번이 사라졌습니다. 순서가 곧 설명인 다섯 장은 항목 사이 간격을 더 길게 뒀습니다.

코드 상자는 밝은 모드에서도 어두운 채로 남습니다. 그래서 코드 안 글자색만은 모드에 따라 바뀌지 않게 고정했습니다. 색을 바뀌는 값으로 두면 어두운 배경에 어두운 글자가 되어 안 보입니다.

발표 중 쓰는 다른 화면도 함께 맞췄습니다. 전체 보기, 인쇄, 밝은 모드, 움직임을 줄이는 설정에서 모두 확인했습니다. 인쇄는 37쪽이고 잘리는 곳도 빈 쪽도 없습니다.

작업 막바지에 겉으로 드러나지 않던 문제 네 가지를 찾아 고쳤습니다. 새로 정한 코드 색이 실제로는 적용되지 않고 원래 색이 남아 있었습니다. 항목이 차례로 나타나야 하는데 전부 한꺼번에 나타나고 있었습니다. 인쇄물 맨 뒤에 빈 쪽이 한 장 붙고 있었습니다. 넷 다 화면에 오류가 안 뜨고 그때의 자동 검사도 통과해서 안 보였습니다. 그때 검사는 링크와 문법만 보고 화면에 실제로 어떻게 그려지는지는 안 봤습니다.

그래서 브라우저로 직접 그려 보고 확인하는 검사를 새로 만들어 넣었습니다. 이 검사는 색이 의도한 값인지, 항목이 차례로 나타나는지, 인쇄가 깨지지 않는지를 봅니다. 검사가 정말 잡는지 확인하려고 네 문제를 하나씩 일부러 되살려 봤습니다. 네 번 다 검사가 실패했고, 되돌리면 다시 통과했습니다. 검사할 때만 브라우저를 내려받고 저장소에는 아무것도 기록하지 않습니다. 검사 대상은 이 발표자료 한 장뿐입니다.

코드 상자의 세로 길이 제한도 없앴습니다. 상자 셋이 원래 제한을 넘어서 어쩔 수 없었습니다. 이제 유일한 제한은 슬라이드 세로 길이입니다. 넘치면 스크롤 막대 없이 그냥 잘립니다. 지금 여유가 가장 적은 두 장은 10픽셀만 남았습니다.

공용 파일과 다른 발표자료는 하나도 건드리지 않았습니다. 바뀐 파일은 이 발표자료 하나뿐입니다.
