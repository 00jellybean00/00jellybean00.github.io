## 스캔 원본 요약

### conventions

기존 슬라이드들은 타이포그래피와 배경 같은 시각 요소를 `assets/` 하위 공용 파일에 분리하여 관리해 왔습니다. 또한 슬라이드 크기(1280x800)를 강제하는 일관된 규칙을 가집니다. 애니메이션의 경우 `fragment`와 `rise` 클래스를 사용하여 각 문서가 자유롭게 개별적인 순차적 동작을 구현할 수 있도록 허용하는 규칙을 따르고 있습니다. 외부 라이브러리는 `vendor/` 디렉터리에 로컬 복사하여 지연 로딩하는 방식을 취하며, 모든 문서는 Playwright 시각 테스트 목록에 포함되어야 합니다. 발표자 화면 최적화(receiver 파라미터) 규칙 역시 존재하나, 이는 현재 각 HTML 파일에 개별적으로 작성되어 있습니다.

### similar-features

과거 공용 테마 분리 작업 시 모든 화면에 통용되는 규칙을 `absci.css` 계열 파일에 두고, 개별 문서는 예외 레이아웃 규칙만 남기는 참조 구조가 성공적으로 쓰였습니다. 화면 전환(Reveal.js 트랜지션)과 요소 동작(CSS 클래스)은 기술적으로 완전히 분리되어 있어, 각 문서의 고유한 애니메이션 설정을 그대로 유지한 채 에셋 내부 디자인만 엡사이(Absci) 테마로 교체할 수 있습니다. 다만, 이번 작업에서는 과거 개별 문서에 흩어져 있던 공통 최적화 로직을 `absci.css` 계열로 이관하기 위해 각 문서의 HTML 구조 수정이 필수적으로 동반됩니다.

### integration-points

이 프로젝트의 자동 검사(CI)는 명암비(AA 등급 4.5:1 이상)와 시차 애니메이션 동작을 픽셀 단위로 매우 엄격하게 검증합니다. 서드파티 라이브러리(Mermaid, Chart.js)의 기존 설정과 새로 도입할 배경색 간 명암 대비가 어긋나면 즉각 CI가 실패합니다. 아울러 기존에 쓰다 버린 구형 스크립트 이름(`starfield.js`)이 검사 설정(GitHub Actions)에 그대로 방치되어 배포 파이프라인 정리가 필수입니다.

### edge-cases

시각 장애인을 위한 애니메이션 끄기 설정과 발표자 화면에서의 로딩 최적화 같은 중요한 처리 로직이 현재는 각 HTML 문서마다 개별적으로 중복 작성되어 있습니다. 또한 인쇄(PDF 변환) 시 화면이 잘리지 않도록 하는 여백 보정 인라인 스타일도 개별 문서마다 따로 존재합니다. 이를 고려하지 않고 배경 디자인만 통합하려 들면, 문서를 갱신하는 과정에서 접근성과 인쇄 기능 등 중요한 예외 상황 대처 코드가 실수로 유실될 위험이 높습니다.
