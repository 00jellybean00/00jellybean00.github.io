# primer-inventory 발표자료 스크립트 작성 및 디자인 개편 Unknown Unknowns

- 스캔 렌즈: conventions / similar-features / integration-points / edge-cases / domain

## 이 문서를 읽기 위한 말

- **덱**: 발표자료 한 벌입니다. 이 저장소에서는 파일 하나가 덱 하나입니다.
- **슬라이드 좌표계**: 슬라이드를 그릴 때 쓰는 가상의 크기입니다.
  화면에 그릴 때는 이 크기를 화면에 맞게 늘리거나 줄입니다.
- **기준 글자 크기**: 슬라이드 안의 모든 글자 크기가 매달려 있는 하나의 값입니다.
  지금은 42픽셀입니다.
- **자동 등장**: 슬라이드가 뜨면 내용이 저절로 순서대로 나타나는 방식입니다.
- **키를 눌러 하나씩**: 방향키를 누를 때마다 항목이 하나씩 나타나는 방식입니다.
- **전체 보기**: `ESC` 키를 누르면 모든 슬라이드가 바둑판처럼 펼쳐지는 화면입니다.
- **움직임 줄이기 설정**: 어지럼증 등을 이유로 애니메이션을 꺼 달라는 운영체제 설정입니다.
- **글자 선명도(대비)**: 글자색과 배경색이 얼마나 다른지를 나타내는 값입니다.
  4.5가 최소 기준이고 7이 권장 기준입니다.
- **발표자 화면**: 발표 중 발표자만 보는 별도 창입니다. `S` 키로 엽니다.
- **자동 검사(CI)**: 코드를 올릴 때마다 저장소가 스스로 돌리는 확인 절차입니다.
- **칸**: 글자 너비가 모두 같은 글꼴에서 글자 한 자리입니다. 한글 한 글자는 두 칸입니다.
- **원문 상자**: 터미널 화면과 코드를 그대로 담아 둔 상자입니다. 덱에 여덟 개 있습니다.
  이 문서에서는 이 이름 하나로 부릅니다.
- **처음 상태를 애니메이션이 정하게 하기(animation-fill-mode: backwards)**:
  움직임이 시작되기 전의 모습을 애니메이션 규칙 안에만 두는 방법입니다.
  움직임이 아예 안 걸리는 상황에서는 요소가 저절로 보이게 됩니다.
- **골라내는 규칙(선택자)**: 어떤 요소에 스타일을 적용할지 지정하는 문장입니다.

### 원문 상자 8개의 새 크기 (해소된 항목 22번의 상세)

기준 글자 크기를 48로 올리고 화면 가로를 1280으로 바꾼 뒤 다시 계산했습니다.
글자에 쓸 수 있는 가로 폭은 1241.6픽셀입니다.
슬라이드 세로는 800픽셀입니다.

상자마다 두 가지를 각각 계산해 **더 작은 값**을 씁니다.
하나는 가로 폭이 허용하는 크기입니다.
다른 하나는 세로 자리가 허용하는 크기입니다.

게다가 그 두 장에는 제목과 설명 글이 함께 들어갑니다.

두 장의 설명 글 분량이 다릅니다.

그래서 상자에 남는 자리가 602픽셀입니다.
탈락 개수 코드는 상자 위에 한 줄, 아래에 두 줄이 붙어 96픽셀을 씁니다.
그래서 상자에 남는 자리가 577픽셀입니다.

세로가 상한인 두 장도 지금보다는 커집니다.
결합 판정 코드는 14.5에서 25.0으로 커집니다.
탈락 개수 코드는 13.2에서 18.2로 커집니다.

**원문 상자의 높이 제한을 없앤다.**
공용 파일이 원문 상자 여덟 개 전부에 480픽셀 제한을 겁니다.
위 표에서 그 값을 넘는 것은 세 개입니다.
부록 코드 512, 결합 판정 코드 602, 탈락 개수 코드 577입니다.
그래서 덱 안에서 이 제한을 **없앱니다.**
대신 슬라이드 세로 800이 유일한 상한이 됩니다.

위 계산은 제목과 설명 글의 높이를 어림한 값입니다.
코드 두 장의 정확한 값은 만들어 보고 재야 정해집니다.
그 확인은 아래 미해소 1번에 적었습니다.

### conventions

색 테마 교체의 구조를 조사했다.

- **공용 팔레트는 `--g-*` 8개뿐이고 다크·라이트 두 벌.** `assets/galaxy.css:4-14` / `:22-31`. 소비처는 `--g-text`가 7곳, `--g-muted`가 10곳, `--g-accent`가 6곳(`--r-link-color-hover`, h3, hero 그라디언트, table th, progress, 랜딩 카드 hover), `--g-scrim`이 전면 막(`galaxy-reveal.css:42`).
- **덮어쓰기는 특정성이 아니라 소스 순서로 이긴다. 단 `:root.light`만 예외.** `galaxy.css`의 `:root`는 (0,1,0)이라 덱 `<style>`의 `:root`가 순서로 이긴다. 그러나 `:root.light`는 (0,2,0)이라 **어떤 순서로도 이긴다** — 덱은 `:root`와 `:root.light` **두 블록을 쌍으로** 써야 하며, 빠뜨리면 `?light`에서 새 테마가 통째로 증발한다.
- **`--r-*`는 `:root`에 쓰면 절반만 먹는다.** `black.css`가 27개를 `:root`에, `galaxy-reveal.css:5-22`가 그중 15개를 `.reveal`에 재선언. 변수 해결은 상속 근접성이므로 재선언된 15개는 반드시 `.reveal`에 써야 한다. 남은 12개(`--r-main-font-size` 포함)만 `:root`에서 먹는다.
- **제목 굵기는 변수로 못 바꾼다.** `galaxy-reveal.css:48`이 `.reveal h1,h2,h3 { font-weight: 700 }`으로 못 박아 `--r-heading-font-weight`를 무력화.
- **변수를 안 쓰고 색을 박아 넣은 곳 9군데.** `galaxy-reveal.css:86`(라이트 pre 배경 `#111827`), `galaxy-reveal.css:10`(`--r-link-color-dark:#3b82f6`), `:12`(선택 영역 파랑), `:87`(라이트 pre 테두리), `:97`(**코드 상자 8개 전부의 배경** `rgba(3,6,14,0.72)`), `:108`(인라인 코드 칩), `:132`(`.figure`), `galaxy.css:41-43`(성운 그라디언트 3겹), `:123`(랜딩 hover). reveal 자체 크롬(`slide-number`, `progress`, `speaker-notes`)도 하드코딩.
- **`?light` 공용 규칙은 정확히 6개**, 그중 `galaxy-reveal.css:84-88`이 지난번 대비 1.04:1 결함의 진원지 — **배경만 다크 고정, 글자색은 라이트 상속** 패턴. 새 팔레트에서 배경 3단계를 라이트에 어떻게 매핑하느냐에 따라 그대로 재발한다.
- **덱은 색을 인라인으로 지정한 곳이 0건.** 인라인 `style` 속성 68개 안의 선언 88개, 분포는 `font-size` 65 / `margin-top` 16 / `text-align` 4 / `margin-bottom` 2 / `margin` 1. 색 경로는 클래스 8개(`.muted` 31곳, `.hero` 4곳, `.tagline` 2곳, `.cite` 2곳, `.cols` 2곳, `h3` 4곳, `table` 9곳, 인라인 `code` 3곳)뿐이라 팔레트만 바꾸면 자동으로 따라온다.
- **monokai는 새 팔레트와 색상환이 어긋난다.** 키워드 `#f92672`(형광 분홍) / 문자열 `#a6e22e`(라임) / 주석 `#75715e`(카키). 실효 배경은 `.hljs`의 `#272822`가 아니라 `galaxy-reveal.css:97`의 `rgba(3,6,14,0.72)`. **라이트 모드에서 주석이 3.62:1로 AA 미달.** 덮어쓰기는 쉽다(monokai는 (0,1,0) 단일 클래스).
- **대비 기준은 이중 기준.** 팔레트 설계는 AAA 7:1(`galaxy.css:3, 20-21`에 실측값 주석), 덱 검수는 AA 4.5:1(Playwright 1920×1080 28장 전수). CI는 대비를 전혀 안 본다.

### integration-points

화면 크기 변경의 접점을 조사했다. **접점 자체는 놀랍도록 좁다.**

- **유일한 코드 접점은 `Reveal.initialize()` 한 곳.** 덱이 지금 `width`/`height`를 아예 안 줘서 reveal 기본값 `{width:960,height:700,margin:.04,minScale:.2,maxScale:2}`를 쓰고 있음. 저장소 전체에 960/700 하드코딩 0건.
- **확대 배율 공식**: `S = min((vw − vw·margin)/width, (vh − vh·margin)/height)`, 이후 minScale/maxScale로 클램프. `margin`은 양쪽 패딩이 아니라 뷰포트 전체에서 한 번 빼는 값이며 슬라이드 좌표계는 줄이지 않는다.

  | 뷰포트 | 960×700 | 1280×800 | 42px 본문의 화면 픽셀 |
  |---|---|---|---|
  | 1920×1080 | 1.4811 | 1.2960 | 62.2 → **54.4** |
  | 1600×900 | 1.2343 | 1.0800 | 51.8 → 45.4 |
  | 1024×768 (4:3) | 1.0240 | **0.7680** | 43.0 → **32.3** |
  | 3840×2160 | 2(클램프) | 2(클램프) | 84.0 → 84.0 |

- **`921.6`은 reveal margin과 무관.** 실제 가용 폭은 `슬라이드 폭 − pre code padding(1.2rem×2 = 38.4px)`. 960에서만 margin 공식(960×0.96)과 우연히 같은 값. 1280에서는 갈라진다 — 패딩 공식 **1241.6**, margin 공식 1228.8. 재계산은 패딩 공식이 맞다.
- **`--r-main-font-size: 42px`는 reveal이 절대 안 건드린다.** 번들에 `main-font-size` 문자열 0건. 크기를 바꿔도 65곳 em의 렌더 크기는 1픽셀도 안 바뀌고 **상대 비중만** 줄어든다(본문이 슬라이드 세로의 6.00% → 5.25%).
- **`galaxy-reveal.css` 절대값 인벤토리**: `reset.css:1`이 `html` 폰트를 재정의하지 않아 **1rem = 16 슬라이드픽셀 고정**. `pre code` padding 38.4px(폭의 4.00% → 3.00%), `max-height:480px`(세로의 68.6% → 60.0%), `.cols` gap 1.2rem(칸 폭 470.4 → 630.4). `theme/black.css`의 `.reveal pre{line-height:1.2em}`은 **덮이지 않아** 코드 상자 줄 높이를 지배 — 높이 역산에 필수.
- **세로 초과의 메커니즘**: `center:true`라 `top = max((height − scrollHeight)/2, 0)`. `scrollHeight > height`면 top이 0에 붙고 `.reveal-viewport`의 `overflow:hidden`이 자른다. 1920×1080 실제 클리핑 지점은 714.6 → **816.7 슬라이드픽셀**. 과거 넘쳤던 4장(774/750/714/735)은 새 800 예산에 전부 들어간다.
- **`starfield.js`는 슬라이드 크기와 완전 무관** — `window.innerWidth/innerHeight`만 씀. 부수 효과 하나: 1920×1080에서 좌우 레터박스가 249px → 130px로 좁아져 **별이 보이는 띠가 절반으로 줄어든다.**
- **발표자 화면은 고정 1100×700**, `getConfig().width`를 안 읽음. `#speaker-controls`는 440×420으로 슬라이드 크기와 무관. 다만 미리보기(`#current-slide` 654×688)의 배율이 0.6540 → **0.4905**로 **25% 작아진다**.
- **`?print-pdf` 페이지는 `floor(크기 × 1.04)`** → 998×728 → **1331×832(13.86in × 8.67in)** 비표준 용지. 인쇄 시 섹션에 `padding:60px 20px`가 붙어 가용 폭 1252.6px로 화면(1241.6)보다 넓다 → **화면 기준으로 맞추면 인쇄는 자동으로 안전**.
- **`alignOne`은 스케일 불변.** 프로브가 `document.body`(스케일 서브트리 **밖**)에 붙어 `getComputedStyle`(transform 미반영)과 같은 좌표계를 쓴다. 우연이 아니라 맞게 되어 있다. 실제로 바뀌는 것은 폰트 크기를 재계산하는 순간이며, 하한 `>= 0.05px`는 크기가 커질수록 넘기기 쉬워져 보정 대상 글자가 늘어난다.
- **CI 함정**: `check-links.js:69`의 정규식은 여는 태그는 속성 없는 것만, **닫는 태그는 아무거나** 잡는다. 새 인라인 `<script>`를 334행(마지막 `text/template`)보다 앞에 넣으면 정규식이 터미널 ASCII 아트를 코드로 먹여 **반드시 실패**한다.

### edge-cases

자동 등장 전환의 실패 모드를 조사했다. **위험도 높음.**

- **슬라이드 번호는 안 바뀐다.** `getTotalSlides()`는 `.slides section:not(.stack)` 개수 — `<section>` 31개 중 stack 3개를 빼 정확히 28. fragment를 다 없애도 `n/28` 유지. **다만 진행 막대는 다르다** — `getProgress()`가 현재 슬라이드의 `.fragment.visible` 비율에 0.9를 곱해 더하므로, 변경 후 26장에서 막대가 계단식으로만 움직인다.
- **코드 줄 강조는 진짜 `.fragment` DOM이다.** 플러그인이 `<code>`를 `cloneNode(true)`로 복제해 `class="fragment"`를 붙이고 `.reveal .hljs:not(:first-child).fragment{position:absolute;top:0;left:0}`로 **절대 위치로 포갠다.** 전용 클래스가 없어 **위치 기반 선택자**(`pre code.fragment`)로만 구분 가능. 전역 규칙을 걸면 클론 4~5개가 동시에 불투명해져 **전 줄이 다 밝은 코드**가 된다. 개수: `:241` 5단계(클론 4), `:334` 6단계(클론 5). 덱 전체 `.fragment` = 28(수작업) + 9(코드) = **37개**.
- **CSS로만 무력화 불가.** `availableRoutes()`가 `.fragment:not(.disabled):not(.visible)`를 보고 `next:true`를 반환하므로, `opacity:1`을 강제해도 화살표가 먼저 소비한다. `.disabled`도 답이 아니다 — reveal이 주는 스타일은 `transition:none` 하나뿐이고 `opacity:0;visibility:hidden`은 그대로. **실제로 제거하는 것 외에 선택지가 없다.**
- **`.present` 게이팅 딜레마.** 안 걸면 `viewDistance:3` 때문에 앞뒤 3장이 미리 로드되어 **도착 3장 전에 애니메이션이 끝나 있다.** 걸면 `yt()`의 `a = L.isActive() || R.isActive()`에 **개요(overview)가 없어** ESC에서 27장이 백지가 된다. reveal의 원래 안전장치 `.reveal.overview .slides section .fragment{opacity:1}`은 `.fragment`를 떼는 순간 함께 사라진다.
- **공용 reduced-motion 규칙이 절반만 덮는다.** `galaxy-reveal.css:151-154`가 `section`과 `section > *`만 잡는데, 이 덱의 등장 대상은 계층이 섞여 있다 — 직계 자식인 fragment 5곳은 잡히고(넷은 `<p>`, 하나는 `<ul>`), `ul`/`ol`/`div`가 직계인 6곳(손자가 실제 항목)은 **안 잡힌다.** base에 `opacity:0`을 두면 reduced-motion 사용자 화면에서 화면 번호 9·13·19·24·26번의 결론 문장이 **영원히 안 보인다.**
- **stack에도 `present`가 붙는다.** 부록이 달린 슬라이드는 부모와 자식 양쪽에 동시에. `section.present > *`는 stack의 직계 자식인 **부록 `<section>` 자체**를 잡아 통째로 밀려 올라온다. `:not(.stack)` 필수.
- **발표자 화면은 `transition=none`만 넘길 뿐 CSS 애니메이션은 못 막는다.** 저장소에 `?receiver` 감지 관용구가 이미 셋(`index.html:695`, `starfield.js:64`, `demo/index.html:218`). 안 끄면 발표자가 다음 내용을 확인하려는 순간 **빈 화면부터 다시 본다.** 부수 효과: Upcoming 창의 의미가 개선된다(지금은 "같은 장에 항목 하나 더" → 앞으로는 실제 다음 슬라이드).
- **인쇄는 오히려 개선된다.** `pdfSeparateFragments:true`라 현재 PDF는 28장 + fragment 37 = **약 65쪽**이고 그중 두 장은 본문 전체가 fragment라 기본 페이지가 제목만 남는다. 나머지 아홉 장은 표나 코드나 문단이 기본 페이지에 남는다. 변경 후 28 + 9 = **약 37쪽**. 다만 코드 2장은 `cloneNode`로 새 요소가 생겨 삽입 시점에 애니메이션이 재시작한다.
- **순서가 논지인 곳 5장** (화면 번호): 15번 `:376-379`(검증 4단 서사), 26번 `:596-604`(질문 → 답, `<ul>` 하나가 통째로 fragment 1개), 9번 `:211`·13번 `:318`·19번 `:479`(표 → 결론 punchline). 그 외 23번 `:544-546`은 첫 항목만 fragment가 아닌 비대칭.
- **`autoAnimate` 지뢰**: 기본 `true`이고 `autoAnimateStyles`에 `opacity`와 `font-size`가 포함. 지금은 `:26` 한 곳뿐이라 짝이 없어 무해하나, 재디자인에서 hero 4장에 일괄로 붙였다가 인접 두 장이 짝이 되면 **등장 애니메이션이 조용히 무력화되고 morph가 뜬다.**
- **되돌아가면 재생된다.** `yt()`가 앞쪽 슬라이드에 `bt()`(모든 fragment를 visible로)를 걸어, 뒤로 돌아가면 이미 다 펼쳐진 상태로 도착. `present`는 같은 태스크 안에서 remove→add 되므로 fragment 이동만으로는 재시작되지 않지만, 슬라이드를 떠났다 오면 매번 재생된다. **코드 슬라이드는 되돌아오면 5~6단계가 전부 visible이 되어 겹친 상태로 도착**하고, 이 상태에서 화살표를 누르면 다음 슬라이드로 넘어간다.
- **CSS만 바꾸는 변경은 CI가 전혀 검증 못 한다.** 개요 백지·reduced-motion 절반 동결·인쇄 공백 세 실패 모드가 전부 CSS 문제이고 어느 것도 CI에 안 걸린다.

### domain

참고 덱의 구현 세부와 발표 스크립트 작성법을 조사했다.

- **참고 덱은 단일 스타일이 아니다.** `.hb-nebula`/`#hero-canvas`는 `intro/index.html`에만 존재. `making-slides`, `knowledge`, `workshop`, `setup`, `security`, `prompt`, `verification`, `orchestration`, `github` 9개는 전부 `body::before` + `body::after` **2겹 CSS 전용 배경**이고 캔버스가 없다. 후자가 저자의 덱 표준.
- **`.autoshow` 전문 (자바스크립트 0줄, `section.present` 후손 선택자만)**:
  ```css
  .autoshow { opacity: 0; }
  section.present .autoshow.fade-up { animation: asFadeUp .6s ease forwards; }
  @keyframes asFadeUp { from { opacity:0; transform: translateY(18px); } to { opacity:1; transform:none; } }
  @keyframes asFadeIn { from { opacity:0; } to { opacity:1; } }
  @keyframes asFadeLeft  { from { opacity:0; transform: translateX(-26px); } to { opacity:1; transform:none; } }
  @keyframes asFadeRight { from { opacity:0; transform: translateX(26px); } to { opacity:1; transform:none; } }
  @keyframes asZoomIn { from { opacity:0; transform: scale(.85); } to { opacity:1; transform:scale(1); } }
  .autoshow:nth-child(1) { animation-delay: .05s; }  /* 이후 .15s 간격으로 8단계까지 */
  ```
  재방문 시 재생됨 — `.present` 제거 → 규칙 소멸 → `opacity:0` 복귀 → 재진입 시 처음부터.
- **`:nth-child` 함정 3가지**: (1) `.autoshow`가 아닌 **모든 형제**를 센다 — `<h2>` 다음 첫 `.autoshow`는 `:nth-child(2)` = 0.2s. (2) 카운터는 부모 기준이라 래퍼 안에서 1부터 재시작. (3) 9번째 이후는 규칙이 없어 `delay: 0`으로 동시 등장.
- **배경 2겹 전문**: `body::before`는 라디얼 3개(보라 0.13 / 민트 0.10 / 분홍 0.04) + `bgFloat 18s ease-in-out infinite alternate`(`translate(-2%,2%) scale(1.05)`). `body::after`는 **도트가 아니라 1px 선 격자** — `linear-gradient` 2개를 56×56px 타일로, 보라 5% 알파, `mask-image: radial-gradient(ellipse at center, rgba(0,0,0,0.85), transparent 75%)`.
- **타이포**: `Pretendard, system-ui` + `JetBrains Mono`. h1 4.2rem / h2 2.9rem / h3 2.0rem, weight 800, `letter-spacing:-0.02em`, `line-height:1.15`. 본문 1.45rem `line-height:1.6`, small 1.18rem, tiny 1.0rem. `text-shadow: 0 1px 0 rgba(0,0,0,.85), 0 2px 4px rgba(0,0,0,.55)`는 **장식이 아니라 그라디언트 배경 위 대비 확보 장치**.
- **reveal 설정**: `width:1280, height:800, margin:0.04, minScale:0.2, maxScale:2.0, center:false, transition:'fade', slideNumber:'c/t'`, 플러그인은 `RevealNotes`만.
- **구문 강조 플러그인이 없다.** highlight.js 미사용, `.kw/.st/.cm/.nm` 4클래스 수작업. `pre.code`는 배경 `#131829`, 테두리 `rgba(255,255,255,0.16)`, 반지름 14px, `white-space: pre-wrap`.
- **밝은 모드가 최대 장벽.** `html{color-scheme:dark}`, `html,body{background:var(--bg-0)!important}`, 헤딩·본문·카드·인용에 `color:#FFFFFF !important`가 직접 박혀 있음. 토큰을 정의해 놓고도 실제 규칙은 리터럴을 씀. **팔레트만 바꿔서는 밝은 모드가 안 나온다.**
- **VDI 대응 이력**: 커밋 `189a815`("보안 인트라넷/VDI에서 애니메이션이 사라지던 문제 수정") — 기업 VDI가 `prefers-reduced-motion: reduce`를 강제해 모든 모션이 죽는 문제를 만나, 미디어 쿼리 대신 **루트 클래스 + localStorage 토글**로 전환.
- **`#hero-canvas` JS는 미확보** — `intro/index.html`이 267KB라 페치 도구 한계로 하단 스크립트 미도달. 대신 동일 저자의 루트 파티클(`#fx`) 전문 확보: DPR `min(dpr,2)` 상한, 입자 수 `min(120, W*H/16000)`, 속도 감쇠 `*.985`, 색은 `hsla(255…)` 보라 / `hsla(168…)` 민트 50:50.
- **발표 스크립트 작성법**: 노트에는 **슬라이드에 없는 것만** 적는다 — 청중은 읽기와 듣기를 동시에 못 하고, "슬라이드를 읽는 것"이 가장 짜증나는 습관 1위(60.4%). 완전한 문장으로 적으면 그대로 읽게 되어 톤이 딱딱해진다. 배치는 4블록 — ① 핵심 주장 한 문장 ② 뒷받침 요점 1~2개 ③ 전달 큐(`[멈춤]`) ④ 빈 줄 후 전환 문장. 형식은 **완전한 문장도 단어도 아닌 구(phrase) 단위 불릿**. 한국어 발화 속도는 분당 280~300자. Q&A 대비는 "예상 질문"이 아니라 **취약점 5축**(유력한 반론 / 데이터가 가장 약한 지점 / 반발할 사람 / 헷갈릴 부분 / 안 다룬 시나리오)으로 뽑고, 답은 문장이 아니라 키워드로 적는다.
