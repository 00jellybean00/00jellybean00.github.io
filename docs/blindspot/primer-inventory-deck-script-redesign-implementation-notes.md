## 2026-07-27 — 본문 글자색을 순백이 아닌 한 단계 낮은 값으로

## 2026-07-27 — 스크립트 상한을 글자 수가 아니라 줄 수로 바꿈

- 결정: 슬라이드당 상한을 140자가 아니라 **8줄**로 잡았다.
- 이유: 140자는 줄바꿈 없는 연속 글을 기준으로 잰 값이었다.
  실제 스크립트는 요점을 줄로 나눠 적는다.
  줄로 나누면 짧은 줄도 한 줄 높이를 다 쓴다.
  그래서 제약이 글자 수가 아니라 줄 수가 된다.
  처음 쓴 초안은 140자를 지켰는데도 스물한 장이 넘쳤다.
- 어떻게 정했나: 발표자 화면 노트 상자를 그대로 재현해 실제 구조로 쟀다.
  8줄은 들어가고 9줄부터 넘쳤다.
  한 줄에 들어가는 글자는 약 18자다.
- 검토한 대안: "노트만 보기" 화면을 쓰라고 안내하는 방법이 있었다.
  사용자가 기본 화면에 스크롤 없이 넣으라고 지시해 버렸다.
- 보수적 선택 여부: 예. 8줄은 실측한 한계값 그대로다. 더 늘리지 않았다.
- 계획과의 이탈: 있음. 설계 문서 결정 3번의 140자 기준을 8줄 기준으로 바꿨다.
  목적은 같다. 발표 중에 스크롤할 일이 없어야 한다는 것이다.
- 사용자 확인 필요: 아니오. 다시 쓴 뒤 28장 전부 넘침 0건을 확인했다.

## 2026-07-27 — 코드 구문 색이 밝은 모드에서 무너진 것을 발견하고 수정

- 결정: 코드 구문 색을 팔레트 변수가 아니라 고정값으로 적었다.
- 이유: 처음에는 변수를 썼다.
  변수는 밝은 모드에서 밝은 배경용 어두운 값으로 바뀐다.
  그런데 코드 상자 배경은 밝은 모드에서도 어두운 채로 남는다.
  어두운 글자에 어두운 배경이 되어 선명도가 2.24까지 떨어졌다.
  밝은 모드에서 미달 항목이 393건 나왔다.
- 이 함정은 설계 문서가 이미 경고한 것이다.
  결정 26번이 "밝은 모드에서도 코드 상자만은 어두운 채로 남는다"고 적었다.
  그런데 구현할 때 그 경고를 구문 색에 적용하지 않았다.
- 검토한 대안: 밝은 모드에서 코드 상자 배경을 밝게 바꾸는 방법이 있었다.
  그러면 코드 색 전체를 밝은 배경용으로 다시 골라야 한다.
  지난 작업에서 상자를 어둡게 유지하기로 이미 정했으므로 버렸다.
- 보수적 선택 여부: 예. 상자 배경이 안 바뀌니 글자색도 안 바뀌게 했다.
- 계획과의 이탈: 없음. 설계 문서 결정 26번을 제대로 지킨 것이다.
- 사용자 확인 필요: 아니오. 수정 후 미달이 393건에서 0건이 되었다.

## 2026-07-27 — 확인 도구가 세 번 틀렸고, 세 번 다 도구를 먼저 고침

- 이유: 이번 확인 단계에서 도구 오류가 세 번 나왔다.
  첫째, 발표자 화면 노트가 넘치는지 재는데 늘어나는 상자를 쟀다.
  늘어나는 상자는 내용이 아무리 길어도 넘침이 잡히지 않는다.
  둘째, 슬라이드 세로 길이를 잴 때 요소 높이를 단순히 더했다.
  위아래로 붙은 여백은 겹쳐서 한 번만 적용되는데 두 번 셌다.
  그래서 멀쩡한 두 장이 넘친다고 나왔다.
