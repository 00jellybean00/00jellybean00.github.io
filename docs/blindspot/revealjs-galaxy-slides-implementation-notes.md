## 2026-07-27 02:05 — 루트 첫 화면을 발표자료 선택 랜딩 페이지로 확정

- 결정: 저장소 루트에 `index.html`을 만든다. 발표자료 목록을 카드로 보여 주고 각 발표자료로 이동시킨다. 지금은 견본 발표자료 하나만 등재한다.
- 이유: 사용자가 명시적으로 요청. unknowns 문서의 해소 1번(첫 화면 파일을 만들지 않는다)과 미해소 1번(첫 화면을 무엇으로 채울지)이 이 요청으로 해소됨.
- 검토한 대안: (a) 루트를 404로 유지하고 `/slides/`만 제공 — 원래 결정이었으나 사용자가 뒤집음. (b) 루트에서 `/slides/`로 자동 전달(redirect) — 발표자료가 여러 개가 될 때 확장 불가라 배제.
- 보수적 선택 여부: 예. 랜딩 페이지의 발표자료 목록을 HTML에 직접 적는다. 목록을 별도 데이터 파일로 분리하지 않는다. 발표자료가 늘어나면 그때 분리한다.
- 계획과의 이탈: 있음. unknowns 해소 1번의 "첫 화면 파일은 이번에 만들지 않는다"에서 벗어남. unknowns 문서를 수정해 반영함.
- 사용자 확인 필요: 아니오 (사용자 지시 자체가 근거)

## 2026-07-27 02:12 — 외부 라이브러리 4종을 저장소에 복사(벤더링), 총 6.6MB

- 결정: reveal.js 6.0.1, KaTeX 0.18.1, Chart.js 4.5.1, Mermaid 11.16.0을 `slides/vendor/` 아래에 실파일로 복사했다. 전부 UMD 빌드만 골랐다.
- 이유: unknowns 해소 3번(저장소에 직접 복사)과 6번(네 기능 모두 포함)을 함께 이행. UMD 빌드는 일반 `<script>` 태그로 불러올 수 있어 브라우저 제약이 가장 적다.
- 검토한 대안: (a) Mermaid의 ESM 빌드(30KB + 조각 파일 다수) — 용량은 1/100이지만 조각 파일을 어느 것까지 복사해야 하는지 불확실하고 `file://`에서 막힌다. (b) 다이어그램·차트를 SVG 그림으로 대체 — 용량 0이지만 사용자가 나중에 글로 다이어그램을 쓸 수 없어 배제.
- 보수적 선택 여부: 예. Mermaid 단일 파일이 3.4MB다. 신규 커밋 대상은 총 6.7MB이고 그중 vendor가 6.6MB다. 조각 분할 최적화는 하지 않고 통짜 파일을 그대로 둔다.
- 계획과의 이탈: 없음. unknowns 해소 21번의 "6번대 최신 버전"대로 reveal.js 6.0.1을 사용. 플러그인 경로가 `dist/plugin/*.js`임을 실물 확인.
- 사용자 확인 필요: 예 — 신규 커밋 6.7MB 중 Mermaid가 3.4MB다. 감수할지, 다이어그램을 그림 파일로 대체할지.

## 2026-07-27 02:26 — 다이어그램을 mermaid.run() 대신 mermaid.render()로 그림

- 결정: `mermaid.run()`을 쓰지 않고 `mermaid.render()`로 화면 밖 임시 칸에서 그린 뒤 결과 SVG만 슬라이드에 옮겨 심는다.
- 이유: reveal은 현재 슬라이드 말고 전부 `display:none`으로 감춘다. 감춰진 칸에서는 글자 크기를 잴 수 없어 `translate(undefined, NaN)` 오류가 났다. 브라우저 콘솔에서 실제로 재현했다.
- 검토한 대안: 슬라이드가 보일 때마다 그리기(`slidechanged` 이벤트) — 매번 다시 그려 느리고, 한 번 그리면 되는 일을 반복한다.
- 보수적 선택 여부: 예. 렌더 실패 시 슬라이드 전체가 멈추지 않도록 `catch`로 감싸고 대체 문구를 넣었다.
- 계획과의 이탈: 없음
- 사용자 확인 필요: 아니오

## 2026-07-27 03:05 — 변경 분석에서 드러난 결함 6건 수정

변경 분석 에이전트가 지적한 항목을 브라우저에서 하나씩 재현해 확인한 뒤 고쳤다. 추측으로 고친 것은 없다.

- 결정 1: 별 애니메이션 루프가 `running`을 확인하도록 고쳤다. 멈출 때 예약도 취소한다.
  - 이유: 실행 도중에 "동작 줄이기"를 켜도 별이 계속 움직였다. 재현 측정값은 켠 뒤에도 프레임 144회. 접근성 약속(unknowns 해소 18번)이 실제로는 지켜지지 않고 있었다. 처음 켠 상태만 확인했기 때문에 놓쳤다. 수정 후 같은 측정값이 2회로 떨어졌다.
- 결정 2: 어둠 막을 별 위로 올렸다. `.reveal-viewport`에 주던 배치·순서 지정을 없앴다.
  - 이유: reveal 6에서 `.reveal-viewport`는 `<body>` 자신이다. 거기에 순서를 주면 body가 별도 쌓임 맥락이 되어, 어둠 막이 별보다 아래로 내려갔다. 즉 별을 전혀 가리지 못했다. unknowns 문서의 네 겹 모형과 실제가 어긋나 있었다.
- 결정 3: 슬라이드 초기화에 실패 처리를 붙였다. 그래프와 다이어그램을 따로 감쌌다.
  - 이유: 다이어그램 설정에서 예외가 나면 그 뒤의 그래프가 통째로 실행되지 않았다. 실패가 콘솔에만 남아 눈치채기 어려웠다.
- 결정 4: 다이어그램 라이브러리(3.4MB)를 필요할 때만 불러오도록 바꿨다. 발표자 화면에서는 아예 안 부른다.
  - 이유: 발표자 화면은 슬라이드를 두 번 더 불러오므로 3.4MB를 세 번 읽고 있었다. 별 애니메이션만 막혀 있었고 이쪽은 뚫려 있었다. 수정 후 발표자 화면 두 칸 모두에서 라이브러리 미로드를 확인했다.
- 결정 5: 그래프 글꼴 지정을 실제 글꼴 이름으로 바꿨다.
  - 이유: `inherit`은 캔버스가 글꼴 이름으로 받지 못한다. 조용히 무시되어 기본값 10px sans-serif로 그려지고 있었다. 브라우저에서 값이 거부되는 것을 직접 확인했다.
- 결정 6: 인쇄 모드에서도 그래프 애니메이션을 끄고, 설정 파일 제외 목록에 `slides/README.md`와 `gemfiles`를 추가했다.
  - 이유: 인쇄 조건이 빠져 있어 그리는 도중 PDF로 찍힐 수 있었다. `slides/README.md`는 제외 목록에 없어 웹에 공개되고 있었다.

- 검토한 대안: 지적 사항을 그대로 수용하기 — 6건 중 3건(루프 누수, 어둠 막 순서, 글꼴 무효값)은 브라우저에서 직접 재현해 확인했고, 나머지 3건은 코드를 읽어 확인했다. 재현되지 않는 지적은 반영하지 않았다.
- 보수적 선택 여부: 예. 리사이즈 처리에 150밀리초 지연만 추가하고 그 이상 손대지 않았다.
- 계획과의 이탈: 없음. 전부 기존 결정을 실제로 지키기 위한 수정.
- 사용자 확인 필요: 아니오

## 2026-07-27 03:40 — KaTeX 폰트 3종 중 2종 삭제, 파비콘 추가

- 이유: KaTeX 스타일시트의 20개 글꼴 규칙 전부에서 `woff2`가 첫 번째다. 브라우저는 첫 지원 형식만 내려받으므로 나머지는 한 번도 요청되지 않는다. 실측으로 확인했다 — 수식 슬라이드에서 요청된 글꼴 4개 전부 `woff2`, `woff`/`ttf` 요청 0건, 실패 자원 0건. 파비콘은 배포된 사이트가 `/favicon.ico`에 404를 내고 있었다.
- 검토한 대안: 3종 전부 유지 — 이전 판단은 "404 소음을 피하려 유지"였으나, 애초에 요청되지 않으므로 소음이 발생하지 않는다는 것이 사실 확인으로 뒤집혔다.
